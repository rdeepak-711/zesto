Glow Zone Bot — What are we building?

Four independent subsystems. Each is its own spec → plan → build cycle. Which do we start with?

💅

A — Service Orders

Customer browses salon menu (wax, facial, manicure…), picks services, gets a WhatsApp order confirmation. No time slot — walk-in style.

Existing cart FSM Low complexity
📅

B — Appointment Booking

Customer picks a service + date + time slot. Slots are checked for availability. Owner gets notified. Customer gets reminder. Needs a slots/bookings table.

New DB tables Medium complexity
🎓

C — Course Enrollment

Customer browses weekend courses (makeup, nailart…), selects batch, pays deposit. Has a course schedule, limited seats per batch. Confirmation + certificate later.

New DB tables Medium complexity
📸

D — Instagram Integration

Pull latest posts from @glowzone4u to show in bot ("see our work"), auto-post before/after promos, DM-to-WhatsApp funnel. Needs Instagram Graph API + webhooks.

External API High complexity

Dependency order: A → B (booking needs services) → C (courses are independent) → D (Instagram is a standalone channel). Building A first gives you the foundation and gets value to the customer fastest.

Which subsystem should we design first?

A

Service Orders first

Simplest, builds on existing cart FSM. Fastest to ship and validate the generic architecture. B naturally follows.

B

Appointment Booking first

The highest-value feature for a salon. Design the slots system first, then service orders slots into it.

AB

A + B together

Design service catalog and booking in one spec since they're tightly coupled. More upfront design work but one cohesive system.

All

Full vision first

Design all 4 at a high level first, then implement in phases. More planning, but avoids rework if later systems change earlier decisions.
